# 探索与发现（Exploration and Discovery）
> 本文整理自 `raw/05_代码与项目/agentic-design-patterns/agentic-design-patterns/27-Chapter-21-Exploration-and-Discovery.md`

---

## TL;DR
探索与发现是面向开放式、复杂或快速演变领域的智能体设计模式，核心是让智能体主动探索陌生领域、尝试新方法、生成新知识，突破预定义知识和解决方案空间的限制，识别**未知之未知**。该模式通常采用多智能体框架模拟人类探索流程（例如科学研究方法），通过分工协作完成探索任务，最终目标是增强而非替代人类能力，加速创新与发现。

---

## 模式定义
探索与发现模式使智能体能够主动寻找新信息、发现新可能性，并识别其运行环境中的未知之未知。它不同于在预定义解决方案空间内的反应式行为或优化，核心特征是：
- 智能体主动进入陌生领域、尝试新方法
- 主动生成新知识与新理解
- 适用于静态知识、预编程方案无法满足需求的开放式、复杂、快速演变领域
- 核心目标是扩展智能体自身的理解与能力

---

## 实际应用场景
AI智能体的智能化优先探索能力可应用于多个领域：
| 应用领域 | 说明 |
|---------|------|
| 科学研究自动化 | 智能体设计运行实验、分析结果、提出新假设，用于发现新材料、候选药物或科学原理 |
| 游戏博弈与策略生成 | 智能体探索游戏状态，发现涌现策略或识别环境漏洞，例如AlphaGo |
| 市场研究和趋势发现 | 智能体扫描非结构化数据（社交媒体、新闻、报告）识别趋势、消费者行为或市场机会 |
| 安全漏洞发现 | 智能体探测系统或代码库发现安全漏洞或攻击向量 |
| 创意内容生成 | 智能体探索风格、主题、数据的组合，生成艺术、音乐或文学作品 |
| 个性化教育和培训 | AI导师根据学生进度、学习风格和薄弱点优先安排学习路径与内容交付 |

## 案例1：Google 协作科学家（Google Co-Scientist）
Google Research开发的基于Gemini大语言模型的多智能体科研协作系统，定位为计算科学协作者，辅助人类科学家完成假设生成、提案优化、实验设计等工作。

### 系统架构
基于多智能体框架，模拟科研的协作迭代流程，由监督智能体在异步任务框架中协调各专业智能体，核心智能体分工如下：
| 智能体角色 | 功能 |
|-----------|------|
| 生成智能体 | 通过文献探索和模拟科学辩论生成初始假设，启动研究流程 |
| 反思智能体 | 作为同行评审，批判性评估生成假设的正确性、新颖性和质量 |
| 排名智能体 | 采用基于Elo评级的竞赛模式，通过模拟科学辩论对假设比较、排名和优先级排序 |
| 演化智能体 | 通过简化概念、综合想法、探索非常规推理，持续优化排名靠前的假设 |
| 邻近智能体 | 计算邻近图对相似想法聚类，协助探索假设空间 |
| 元评审智能体 | 综合所有评审和辩论的见解，识别共同模式并提供反馈，支持系统持续改进 |

系统基于Gemini提供语言理解、推理和生成能力，采用**测试时计算扩展**机制分配更多计算资源迭代推理优化输出，可处理综合学术文献、网络数据、数据库等多来源信息。

### 工作流程
遵循迭代的「生成、辩论和演化」流程，匹配科学方法：
1. 接收人类科学家输入的科学问题
2. 进入假设生成→评估→优化的自我改进循环
3. 假设经过智能体内部评估、竞赛排名机制的系统性筛选

### 验证结果
已在生物医学领域完成多项验证，通过自动化基准、专家评审、端到端湿实验验证了实用性：
1. **自动化与专家评估**：在GPQA基准困难的「钻石集」上top-1准确率达到78.4%，系统内部Elo评级与结果准确性一致；对200+研究目标的分析显示，扩展测试时计算可稳定提升假设质量；在15个挑战性问题上表现优于其他SOTA AI模型和人类专家的「最佳猜测」；生物医学专家认为其输出比基线模型更新颖、更具影响力；药物重定位提案被六位肿瘤学专家评为高质量。
2. **端到端实验验证**：
   - 急性髓系白血病（AML）药物重定位：提出完全新颖的候选药物KIRA6，体外实验证实KIRA6可在临床相关浓度下抑制多个AML细胞系的肿瘤活力
   - 肝纤维化新靶点发现：识别出全新表观遗传靶点，人类肝脏类器官实验证实靶向该靶点的药物具有显著抗纤维化活性，其中一种已被FDA批准用于其他适应症，具备再利用潜力
   - 抗菌素耐药性研究：独立重现了一个研究团队耗时十多年才得到的未发表实验结论，仅用两天就得到了相同的顶级假设：`cf-PICIs与不同噬菌体尾部相互作用以扩大宿主范围`

### 局限性与安全
- **设计理念**：强调增强人类研究而非完全自动化，采用「科学家在回路中」的协作范式，人类可通过自然语言指导系统、提供反馈
- **局限性**：知识受限于开放获取文献，可能遗漏付费墙内容；难以获取极少发表但对科研至关重要的负面实验结果；继承大语言模型的幻觉、事实不准确问题
- **安全机制**：输入和输出均做安全审查，防止被用于不安全不端研究；1200个对抗性目标测试显示系统可稳定拒绝危险输入；目前通过可信测试者计划开放获取，收集真实世界反馈

## 案例2：Agent Laboratory 实战框架
Samuel Schmidgall在MIT许可证下开发的自主科研工作流框架，定位为增强而非替代人类科研工作，通过自动化科研各阶段让人类研究者专注于概念化和批判性分析，集成了去中心化自主研究智能体存储库AgentRxiv。

### 研究流程
分为四个明确阶段：
1. **文献综述**：专用LLM智能体自主收集、分析相关学术文献，利用arXiv等数据库识别、综合、分类研究，建立后续流程的知识库
2. **实验**：协作制定实验设计、准备数据、执行实验、分析结果；智能体使用Python生成执行代码、通过Hugging Face访问模型，可根据实时结果迭代优化实验流程
3. **报告撰写**：自动生成综合研究报告，结合实验发现和文献综述见解，按照学术规范排版，可集成LaTeX完成专业格式和图表生成
4. **知识共享**：通过AgentRxiv平台支持智能体共享、访问、协作推进科学发现，支持累积性研究进展

### 核心设计：多智能体层级结构
模仿学术研究团队的分工结构：
- **教授智能体**：研究主管，负责制定研究议程、定义研究问题、向其他智能体委派任务，把控战略方向，保证符合项目目标
- **博士后智能体**：研究执行者，负责文献综述、设计实施实验、生成论文等研究成果，具备编写执行代码能力，是研究产出的主要生产者
- **评审智能体**：对博士后产出做批判性评估，评估论文和实验结果的质量、有效性、科学性，模拟学术同行评审保证产出质量
- **机器学习工程智能体**：承担机器学习工程师角色，和博士生协作开发简单的数据预处理代码，整合文献和实验方案的见解，保证数据符合实验要求
- **软件工程智能体**：指导机器学习工程智能体，保证生成的代码简单、直接符合研究目标
